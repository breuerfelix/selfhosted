# KOReader Sync Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deploy the official KOReader sync service at `https://kosync.felixbreuer.me`.

**Architecture:** A single container includes the sync server and Redis. Existing Flux, Traefik, cert-manager, retained host storage, and nightly backups provide the surrounding infrastructure.

**Tech Stack:** Kubernetes manifests, Kustomize, Flux, Ansible, official `koreader/kosync` image.

**Spec:** `docs/superpowers/specs/2026-11-23-kosync-design.md`

## Global Constraints

- One replica, `Recreate`, no scheduling constraints, no separate Redis or custom image.
- Retained static storage uses `hostPath` with `type: Directory`, explicit claims, and `Retain`; preserve existing data paths and ownership.
- Use `/data/kosync`, `apps/kosync`, `kosync-data`, HTTP `17200`, and HTTPS `kosync.felixbreuer.me`.
- No ad hoc backups. Extend the existing nightly backup target list.
- Leave registration enabled for initial reader account creation; document disabling it afterward.

## Review Focus

- Wrong upstream protocol or port: test public HTTPS health and HTTP redirection.
- Missing or misbound persistence: assert PV/PVC identities and verify progress after a replacement Pod.
- Unauthenticated access: assert progress endpoints reject missing or incorrect credentials.
- Backup omission: assert `apps/kosync` in the rendered cluster backup patch and check the live ConfigMap.
- Existing services or data affected: change only the new app, directory, backup target, and supporting documentation; remove only temporary test resources and their keys.
